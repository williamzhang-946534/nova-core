# Nova Duck ESP32 桌面机器人 MVP

## 1. 定位与边界

本方案为 Arvuno 长期具身智能路线中的独立硬件验证子线，代号 **Nova Duck**。目标是制作一个放在桌面上的小型表情/语音/头部动作机器人，用来验证机器人本体控制、感知入口、状态上报、失效保护和未来 Robot Adapter 边界。

`hardware/nova-duck-esp32/` 是 Nova Duck 的唯一子项目根目录。后续固件、电路、结构、采购、测试记录和验收材料都默认放在本目录及其子目录中，不散落到 Arvuno Core 的 `docs/`、`backend/` 或 `frontend/`。

Nova Duck 不是智元商用机器人的替代品，也不是当前 Arvuno Core 的正式模块。第一阶段只做低风险桌面形态，不做全屋导航、机械臂抓取、越障移动和无人值守自主任务。

### 1.1 目标

1. 通过 ESP32-S3 完成显示、声音、头部动作和状态管理的最小闭环。
2. 建立机器人本体的安全约束、命令校验、心跳、看门狗和失效回退。
3. 用低成本硬件验证未来具身智能产品形态。
4. 为 Arvuno 未来 Robot Adapter 提供真实观测数据，但不在本阶段直接接入 Arvuno Core。

### 1.2 非目标

1. 不做全屋移动机器人。
2. 不做机械臂、夹爪或任何接触人身的动作。
3. 不把 ESP32 当作大模型推理设备。
4. 不把机器人命令伪装成普通灯/开关设备。
5. 不做云端公网控制，第一阶段仅允许局域网控制。
6. 不允许绕过物理断电和急停机制。

## 2. 产品形态

### 2.1 MVP 形态

一个高度约 120-180 mm 的桌面小机器人，外形可以采用小黄鸭或圆润宠物风格。上半身包含圆形/方形 TFT 表情屏，头部由 2 个舵机驱动，可实现俯仰和偏航。底部加重防倾倒，固定放在桌面上。

交互能力：

1. 表情动画：开心、好奇、思考、提醒、错误、休眠。
2. 头部动作：点头、摇头、看向左右、回中、休眠姿态。
3. 语音提示：本地提示音、TTS 播放、音量控制。
4. 状态显示：在线、离线、升级、低电量、急停。
5. 桌面控制：局域网 Web 页面手动控制，不接云。

### 2.2 后续扩展

| 阶段 | 能力 | 前提 |
| --- | --- | --- |
| V1 | 表情 + 头部动作 + 状态上报 | 本文档 MVP |
| V1.5 | 麦克风输入 + 云/本机 ASR + TTS | 麦克风授权、录音状态灯、数据保留策略完成 |
| V2 | OV2640 摄像头按需拍照 | 摄像头授权、隐私提示、默认关闭完成 |
| V3 | 三轮/四轮桌面小车底座 | 防跌落、碰撞保护、禁行边界、急停完成 |
| V4 | Arvuno Robot Adapter | 独立安全设计、权限模型、任务模型和验收完成 |

## 3. 硬件选型

### 3.1 推荐核心配置

| 模块 | 推荐型号 | 说明 | 预算参考 |
| --- | --- | --- | --- |
| 主控 | ESP32-S3-N16R8 DevKit | 16 MB Flash、8 MB PSRAM，适合 LVGL、音频缓冲和摄像头扩展 | 45-80 元 |
| 表情屏 | 1.9/2.0/2.4 英寸 ST7789 SPI IPS，170x320 或 240x320 | 圆角外观优先，亮度可控制 | 35-70 元 |
| 舵机 | MG90S 或 ES08MA II，2 个 | 金属齿更耐用，力矩足够驱动头部 | 40-60 元 |
| 功放 | MAX98357A I2S | 直接接 3-4 欧喇叭，避免模拟音频噪声 | 8-15 元 |
| 喇叭 | 4 欧 3W，28-40 mm | 桌面音量足够，注意腔体 | 5-12 元 |
| 麦克风 | INMP441 或 MSM261 I2S | V1 可先不装，V1.5 启用 | 8-15 元 |
| 传感器 | MPU6050/ICM-20948、电压电流检测 | 姿态、掉落和电池监测可选 | 10-25 元 |
| 电源 | USB-C 5V/3A 或 18650 + 升压板 | 舵机与主控建议分路供电 | 15-60 元 |
| 结构 | 3D 打印 PLA/PETG + 配重 + 橡胶脚垫 | 底部加重防倾倒 | 20-60 元 |
| 其他 | 触摸/按键、LED、开关、杜邦线、排针 | 急停和状态提示 | 10-25 元 |

MVP 预算约 **180-400 元**。若加入摄像头、电池和更高规格结构件，约 **350-600 元**。

### 3.2 供电要求

1. 主控和屏幕由稳定 5V/1A 供电。
2. 舵机单独由 5V/2A 以上供电，避免舵机启动电流导致 ESP32 复位。
3. 主控、舵机、功放必须共地。
4. 舵机电源入口并联 470-1000 uF 电容，并配置可恢复保险丝。
5. 电池版本必须有过充、过放、过流和短路保护。
6. 物理电源开关是第一级急停，软件急停只作为辅助，不能替代断电。

### 3.3 引脚规划草案

以下为 ESP32-S3 常见引脚的初稿，最终必须根据实际开发板原理图和壳体走线复核，避开 strapping pin。

| 功能 | 建议 GPIO | 备注 |
| --- | --- | --- |
| TFT SCK | 12 | SPI 时钟 |
| TFT MOSI | 11 | SPI 数据 |
| TFT DC | 10 | 数据/命令 |
| TFT CS | 9 | 片选 |
| TFT RST | 14 | 复位 |
| TFT BL | 21 | PWM 背光 |
| Neck yaw servo | 38 | LEDC PWM，50 Hz |
| Neck pitch servo | 39 | LEDC PWM，50 Hz |
| Mic SCK / WS / SD | 4 / 5 / 6 | V1.5 启用 |
| Speaker BCLK / LRC / DIN | 15 / 16 / 7 | I2S 输出 |
| I2C SDA / SCL | 8 / 17 | IMU 等可选 |
| User button | 1 | 内部上拉，按下接地 |
| Status LED | 2 | 在线/录音/错误状态 |
| E-stop input | 18 | 断电检测或急停反馈 |

禁止使用 GPIO 0、3、45、46 承担运行时关键功能，除非完成启动状态验证。

## 4. 系统架构

```text
局域网 Web 控制台 / 诊断工具
        │ WebSocket 或 MQTT
        ▼
Nova Duck ESP32 Firmware
├─ Network Service：连接、鉴权、心跳、OTA
├─ Command Service：Schema 校验、去重、限流、过期处理
├─ Safety Service：急停、角度边界、速度限制、温度/电压检查
├─ Motion Service：舵机限位、缓动、回中、休眠
├─ Expression Service：LVGL 表情与状态动画
├─ Audio Service：提示音、TTS 播放、音量
├─ Telemetry Service：健康状态、事件、日志
└─ Watchdog / Failsafe：心跳丢失、断连、异常自动回中并停用
```

### 4.1 控制边界

ESP32 负责实时动作与失效保护；电脑或后续 Arvuno Core 只发送高层命令，例如：

1. `set_expression`
2. `speak`
3. `look`
4. `nod`
5. `shake_head`
6. `center`
7. `sleep`
8. `report_status`

上层不允许直接输出舵机 PWM、强制角度、无限等待或连续底层电机指令。

### 4.2 安全规则

1. 头部俯仰建议限位 `-20°..+20°`，偏航建议限位 `-70°..+70°`，装配后必须重新标定。
2. 所有动作必须使用缓动曲线，禁止立即跳变。
3. 单次动作默认最长 3 秒，超时自动停止。
4. 命令必须带 `message_id` 和 `expires_at`，重复或过期命令拒绝执行。
5. 断连超过 5 秒，头部回中并进入安全姿态。
6. 低电压、过流、姿态异常或高温时停止动作并显示错误。
7. 每秒限制动作命令次数，默认不超过 5 次。
8. OTA 只允许在电池充足和外接电源时执行，失败必须可回滚。
9. 麦克风和摄像头默认关闭，启用时必须有可见状态灯。
10. 每次急停、断连、过流和掉落事件必须保存最近事件日志。

## 5. 通信协议

第一阶段建议先使用局域网 WebSocket，便于 Web 控制台联调；第二阶段迁移 MQTT，便于后续与 Arvuno 的 Reality Adapter 生态统一。

### 5.1 命令格式

```json
{
  "type": "command",
  "message_id": "01J8ZD5Y7Q9K8V2M3N6R",
  "issued_at": "2026-11-02T08:30:00Z",
  "expires_at": "2026-11-02T08:30:05Z",
  "command": "look",
  "params": {
    "yaw_deg": 30,
    "pitch_deg": 0,
    "duration_ms": 800
  }
}
```

### 5.2 状态格式

```json
{
  "type": "telemetry",
  "robot_id": "nova-duck-001",
  "firmware": "0.1.0",
  "mode": "active",
  "estop": false,
  "battery": {
    "level": 0.82,
    "voltage": 4.05
  },
  "motion": {
    "yaw_deg": 12,
    "pitch_deg": -3,
    "moving": false
  },
  "sensors": {
    "temperature_c": 41.2,
    "upright": true
  },
  "network": {
    "rssi": -52,
    "ip": "192.168.1.23"
  }
}
```

### 5.3 错误码

| 错误码 | 含义 | 安全动作 |
| --- | --- | --- |
| `INVALID_SCHEMA` | 参数非法 | 拒绝命令 |
| `COMMAND_EXPIRED` | 命令过期 | 拒绝命令 |
| `DUPLICATE_MESSAGE` | 重复消息 | 返回原结果，不重复执行 |
| `ESTOP_ACTIVE` | 急停生效 | 拒绝动作 |
| `OUT_OF_LIMIT` | 角度或速度超限 | 拒绝动作 |
| `LOW_BATTERY` | 电量不足 | 停止动作并提示 |
| `HEARTBEAT_TIMEOUT` | 控制端失联 | 回中并进入安全态 |
| `OVERHEAT` | 温度过高 | 停用舵机 |
| `NOT_UPRIGHT` | 机器人倾倒 | 停用舵机并报警 |

## 6. 制造与装配路线

### 6.1 第一轮技术验证

不打印外壳，先用面包板或亚克力板固定主控、屏幕和两个舵机，验证：

1. ESP32-S3 启动、Wi-Fi、OTA 和看门狗。
2. ST7789 显示帧率与亮度控制。
3. 舵机限位、回中和缓动。
4. I2S 音频播放是否可接受。
5. 舵机启动时主控是否复位。
6. 断连 5 秒后是否能自动回中。

### 6.2 第二轮结构原型

1. 用 3D 打印制作头部支架、舵机摇臂和底座。
2. 底部加入配重，重心应位于底座中心且低于头部舵机轴。
3. 屏幕与头部一起运动，线缆预留弯曲半径。
4. 验证连续运行 30 分钟无卡死、无异响、无过热。
5. 测试倾倒、堵转、断电、断网和 OTA 失败场景。

### 6.3 第三轮外观版本

1. 完成小黄鸭或圆润宠物外壳。
2. 喇叭、麦克风和状态灯位置避免遮挡。
3. 加入电源开关、充电口和急停断电开关。
4. 拆装不需要破坏结构件，屏幕和舵机可更换。
5. 在桌面边缘测试防倾倒，禁止在边缘开启大幅动作。

## 7. 软件里程碑

### M0：方案与采购

产出：BOM、结构草图、引脚表、风险清单、采购单。

验收：确认主控实际引脚、舵机行程、屏幕驱动和供电方案。

### M1：最小固件

内容：Wi-Fi 连接、时间同步、健康接口、OTA、看门狗、日志。

验收：连续运行 2 小时无复位；OTA 成功并可回滚；断电重启后自动恢复安全态。

### M2：表情与动作

内容：ST7789/LVGL 表情动画、两个舵机缓动、限位、回中、休眠。

验收：动作流畅无抖动；命令非法时拒绝；断网后回中；倾倒时停止。

### M3：音频与本地控制台

内容：I2S 播放、音量控制、提示音、局域网 Web 控制台。

验收：控制台可查看状态、切换表情、触发动作和播放音频；无云依赖。

### M4：安全与耐久

内容：命令去重、限流、事件日志、低电压/温度/姿态保护、异常注入测试。

验收：急停、断连、堵转、低电、倾倒、OTA 失败全部进入预期安全态。

### M5：Arvuno 接入评估

内容：设计 Robot Capability Schema、状态映射、权限模型和仿真测试。

验收：形成独立 ADR 和接口设计，不直接修改现有 Device Adapter。

## 9. 采购优先级

## 10. 结论

Nova Duck 的第一版应聚焦“桌面、低风险、可见、可停、可恢复”。它先用 ESP32-S3 验证机器人本体的显示、声音、动作、状态和安全失效机制；等硬件稳定后，再通过独立 Robot Adapter 进入 Arvuno。该子线不改变 Arvuno Core 当前阶段边界，也不把实体硬件验收混入已完成的第一阶段结论。
