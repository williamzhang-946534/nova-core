# 13. 开发路线图

## 总体原则

1. 架构确认后才进入工程初始化。
2. 每个阶段先做最小可用版本。
3. 真实设备写操作必须在安全链路测试通过后开放。
4. 每个阶段都有明确验收标准。
5. 不引入当前阶段用不到的复杂依赖。

## 阶段总览

| 阶段 | 名称 | 目标 | 是否必须 |
| --- | --- | --- | --- |
| Phase 0 | 架构确认 | 确认文档和边界 | 是 |
| Phase 1 | 工程初始化 | 建立可运行工程骨架 | 是 |
| Phase 2 | 数据与配置 | 建立数据库、配置和日志 | 是 |
| Phase 3 | 设备接入 | 打通 Home Assistant 和 Mock | 是 |
| Phase 4 | 环境与事件 | 建立上下文和事件系统 | 是 |
| Phase 5 | 安全工具执行 | 实现工具、权限和验证 | 是 |
| Phase 6 | 任务系统 | 支持多步骤任务和状态机 | 是 |
| Phase 7 | AI Agent | 接入模型并实现意图与规划 | 是 |
| Phase 8 | Web 控制台 | 提供核心页面 | 是 |
| Phase 9 | 自动化与通知 | 提供 Nova 上下文通知和少量确认后低风险自动化 | 是 |
| Phase 10 | 稳定化验收 | 完成第一阶段验收 | 是 |

## Phase 0：架构确认

### 目标

用户确认架构文档、模块边界、数据模型、安全策略和第一阶段范围。

### 交付物

- 当前架构文档
- AGENTS.md
- README.md

### 验收标准

1. 用户确认技术栈。
2. 用户确认 Home Assistant 边界。
3. 用户确认第一阶段不开发内容。
4. 用户确认安全策略。
5. 用户确认开发顺序。

### 不做

- 不初始化代码。
- 不安装依赖。
- 不实现业务功能。

## Phase 1：工程初始化

当前进度：已完成（2026-10-26，用户已继续进入 Phase 2）。

### 目标

建立后端、前端和测试基础骨架。

### 任务

1. 初始化 Git 仓库。
2. 创建后端目录结构。
3. 创建前端目录结构。
4. 创建 `.env.example`。
5. 创建 Windows 启动脚本设计。
6. 配置代码格式化。
7. 配置测试框架。
8. 建立基础错误模型。
9. 建立日志框架。

### 验收标准

1. 后端可以启动。
2. `/health` 可以访问。
3. 前端可以启动。
4. 前端可以请求后端健康检查。
5. 单元测试可以运行。
6. OpenAPI 文档可以生成。
7. 敏感信息不入库。

## Phase 2：数据与配置

当前进度：已完成（2026-10-26，待用户验收）。

### 目标

完成配置、数据库模型、迁移和基础仓储。

### 任务

1. 实现 Pydantic Settings。
2. 定义数据库表。
3. 创建 Alembic 迁移。
4. 实现 Repository 边界。
5. 实现日志目录。
6. 实现数据库初始化。
7. 实现基础备份方案。

### 验收标准

1. 首次启动可以自动迁移或按脚本迁移。
2. 核心表结构创建成功。
3. 配置缺失时报错明确。
4. API Key 不出现在日志。
5. 数据库可以备份和恢复。

## Phase 3：设备接入

当前进度：已完成（2026-10-26，待用户验收）。

### 目标

建立统一设备接口，并实现 Home Assistant 与 Mock 两个适配器。

### 任务

1. 定义 Device Adapter Interface。
2. 定义 Device、State、Capability、Action 模型。
3. 实现 Home Assistant 健康检查。
4. 实现轻量 Device Registry 投影同步，仅同步配置范围内允许 Nova 使用的实体。
5. 实现状态查询。
6. 实现低风险动作调用。
7. 实现状态变化订阅或轮询。
8. 实现轻量 Device Registry。
9. 实现 Mock Device Adapter。

### 验收标准

1. 能连接 Home Assistant。
2. 能只同步配置范围内的有限设备，不同步 Home Assistant 全部实体和完整配置。
3. 能读取状态。
4. 能识别 unavailable。
5. 能控制一个低风险设备。
6. Mock Adapter 可以模拟离线和超时。
7. 适配器错误统一。

### 风险控制

真实设备写操作只能在 Safety Policy 和 Tool Executor 完成后开放。此阶段可以先提供开发模式开关，默认关闭。

## Phase 4：环境与事件

当前进度：已完成（2026-10-27，待用户验收）。

### 目标

建立 Nova 自己的环境上下文和事件系统。

### 任务

1. 定义 Event Schema。
2. 实现应用内事件总线。
3. 实现过滤后的 Nova 领域事件持久化。
4. 实现事件查询 API。
5. 实现环境状态快照。
6. 将设备状态更新写入 Environment Context。
7. 支持 correlation ID。

### 验收标准

1. 配置范围内与 Nova 相关的设备状态变化生成事件。
2. 事件入库。
3. Environment Context 更新。
4. 事件时间线可查询。
5. 事件保留策略可配置。
6. 订阅者异常不影响主流程。

## Phase 5：安全工具执行

当前进度：已完成（2026-10-27，待用户验收）。

### 目标

让所有设备操作都通过统一、可审计、可验证的工具链路。

### 任务

1. 定义 Tool Schema。
2. 实现 Tool Registry。
3. 实现 Safety Policy。
4. 实现 Tool Executor。
5. 实现参数校验。
6. 实现设备权限。
7. 实现风险等级。
8. 实现用户确认。
9. 实现执行结果验证。
10. 实现 ToolExecutionRecord。

### 验收标准

1. 只读工具可用。
2. low_risk 设备控制可用。
3. medium_risk 需要确认。
4. high_risk 默认拒绝。
5. 非法参数拒绝。
6. 设备离线拒绝。
7. 状态验证失败时任务不成功。
8. 每次执行有日志。

## Phase 6：任务系统

### 目标

将用户目标或自动化触发转化为可管理任务。

### 任务

1. 实现 Task 和 TaskStep 模型。
2. 实现任务状态机。
3. 实现计划存储。
4. 实现步骤执行。
5. 实现失败、取消和超时。
6. 实现任务历史查询。
7. 实现任务事件。

### 验收标准

1. 单步任务可执行。
2. 多步任务可执行。
3. 失败状态正确。
4. 取消状态正确。
5. 超时状态正确。
6. 任务历史完整。
7. correlation ID 可追踪。

### 当前完成情况

Phase 6 已按最小可用范围完成并等待用户验收。实现包含 Task/TaskStep Repository、任务和步骤状态机、显式计划保存、顺序步骤执行、失败传播、取消、执行超时、等待确认超时、历史分页查询、任务事件和 correlation ID 贯穿。TaskStep 统一通过既有 Tool Executor 调用工具，未复制设备执行逻辑，也未绕过 Safety Policy。测试使用显式任务输入、Mock Device Adapter 和真实 Tool Executor 闭环。

## Phase 7：AI Agent

### 目标

接入统一 AI Provider，实现自然语言查询和低风险控制。

### 任务

1. 实现 Provider Interface。
2. 实现 OpenAI-compatible Provider。
3. 实现结构化输出校验。
4. 实现意图识别。
5. 实现工具定义下发。
6. 实现候选计划生成。
7. 实现 Agent 与 Task System 集成。
8. 实现工具结果处理。
9. 实现模型调用日志。

### 验收标准

1. 可用自然语言查询设备。
2. 可用自然语言查询环境。
3. 可执行低风险设备控制。
4. 不支持意图不误执行。
5. 模型输出非法时拒绝执行。
6. Provider 超时不导致任务假成功。
7. 可更换模型配置。

提供 Nova 的运行与观测界面。

### 任务

3. 设备详情。
4. 环境状态。

8. 工具调用详情。

1. 页面可正常访问。

## Phase 9：自动化与通知

### 目标

普通定时、状态触发和场景自动化继续留在 Home Assistant。Nova 只实现需要自身上下文的少量通知规则、任务失败提醒和可选的确认后低风险动作规则。

### 任务

1. 少量 Nova 上下文自动化规则模型。
2. 条件评估。
3. 事件触发。
4. 冷却时间。
5. 自动化执行记录。
6. Web 控制台通知。
7. 任务失败通知。

### 验收标准

1. 少量明确启用的通知规则可用。
2. 任务失败通知可用。
3. 经用户确认的低风险动作规则可用。
4. 设备状态规则仅覆盖 Nova 实际需要的场景，不做通用自动化平台。
5. 冷却时间生效。
6. 自动化执行有记录。
7. 失败可追踪。
8. 高风险自动化不自动执行。

## Phase 10：稳定化验收

### 目标

完成第一阶段闭环和稳定性验证。

### 任务

1. 补齐安全测试。
2. 补齐验收测试。
3. 检查日志和脱敏。
4. 验证备份恢复。
5. 验证断线重连。
6. 验证 Mock 全流程。
7. 验证真实 Home Assistant 全流程。
8. 更新文档。

### 验收标准

Nova 能完成：

```text
真实环境信息
→ 自然语言目标
→ 任务计划
→ 安全工具执行
→ 设备状态验证
→ 任务历史记录
→ Web 控制台展示
```

设备异常、超时、模型错误和权限错误均有明确处理。

1. 设备标准模型
2. 事件格式
3. 任务状态机
4. 工具风险等级
5. 用户确认机制

## 不应现在开发的功能

1. 老人监护相关功能
2. 自研智能家居协议
3. 多 Agent 协作
4. 插件市场
5. 多租户 SaaS
6. 完整视频监控
7. 复杂机器人控制
8. 高风险设备自动化
9. 向量数据库
10. Kubernetes

## 维护成本分析

| 成本 | 评估 |
| --- | --- |
| 日常运行 | 单后端 + SQLite，成本低 |
| 调试 | 本地进程和结构化日志，较容易 |
| 测试 | Mock 设备和 Provider，可离线测试 |
| 数据库 | 单文件备份，简单 |
| 扩展 | 通过接口新增适配器和工具 |
| 主要风险 | Python 经验较少、外部 API 变化、真实设备状态不稳定 |

控制方式：

- 保持小模块。
- 每阶段有验收。
- 不引入额外基础设施。
- 核心安全逻辑优先测试。

## 第一阶段开始建议

Nova Core 已完成工程初始化、数据配置、设备接入、环境状态、事件系统、安全工具执行和任务系统基础。下一阶段应从 AI Provider 与 Agent Runtime 开始，继续保持小模块和明确安全边界。

Phase 6 已完成显式任务计划、TaskStep 执行、任务历史、失败、取消、超时和任务事件。真实 Home Assistant 写操作保持默认关闭。Phase 6 等待用户验收，确认后才进入 Phase 7 AI Agent。
