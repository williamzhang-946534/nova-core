# 10. 记忆系统设计

## 目标

Memory System 让 Arvuno 能区分实时状态、历史事实、用户偏好和任务经验，并按授权、用途和保留策略管理这些信息。

第一阶段不引入向量数据库，先实现结构化记忆接口和简单检索。

## 记忆分类

| 类型 | 说明 | 存储 | 生命周期 |
| --- | --- | --- | --- |
| Short-term Context | 当前对话和任务上下文 | 对话消息、任务上下文 | 会话或短期 |
| Device State | 设备当前状态 | Environment Context / Device State | 实时 |
| Event History | 事件历史 | events 表 | 按保留策略 |
| User Preference | 用户偏好 | user_preferences | 长期，可编辑 |
| Long-term Memory | 用户确认的重要事实和经验 | memories | 长期，可删除 |
| Task Memory | 任务执行经验和结果摘要 | tasks / memories | 长期 |

## 明确边界

### 实时状态

包括：

- 设备开闭状态
- 传感器读数
- 设备在线状态
- 当前活动任务

特点：

- 可以随时被新数据覆盖。
- 不作为长期事实保存。
- 掉线或重启后可重新同步。

### 历史事件

包括：

- 状态变化
- 传感器更新
- 任务事件
- 工具执行事件

特点：

- 只追加，不随意改写。
- 用于时间线和自动化判断。
- 按策略清理。

### 用户偏好

包括：

- 常用设备称呼
- 默认区域
- 温度偏好
- 通知偏好
- 自动化偏好

特点：
- 必须结构化。
- 用户可查看、修改和删除。
- 不能从单次猜测中直接永久保存，重要偏好需要确认。

### 长期记忆

包括：

- 用户明确提供的事实
- 重复出现的偏好
- 任务经验摘要
- 用户确认的使用习惯

特点：
- 必须有来源。
- 必须可删除。
- 敏感信息需要显式授权。

### 不属于长期记忆

- 所有原始聊天记录
- 未筛选的设备事件
- 模型中间推理
- API Key 和密钥
- 用户未确认的猜测

## 记忆接口

```python
class MemoryStore(Protocol):
    async def add(self, entry: MemoryInput) -> Memory: ...

    async def search(self, query: MemoryQuery) -> list[Memory]: ...

    async def get(self, memory_id: str) -> Memory: ...

    async def update(self, memory_id: str, patch: MemoryPatch) -> Memory: ...

    async def forget(self, memory_id: str) -> None: ...

    async def list_by_source(
        self,
        source_type: str,
        source_id: str,
    ) -> list[Memory]: ...
```

接口是设计规范，不代表当前阶段实现代码。

## 记忆写入来源

| 来源 | 允许写入 | 条件 |
| --- | --- | --- |
| 用户明确陈述 | 是 | 用户在对话中明确提供 |
| 用户偏好设置 | 是 | 用户在设置中提交 |
| 任务经验 | 是 | 任务完成后生成摘要 |
| Agent 猜测 | 受限 | 标记为未确认，不进入长期记忆 |
| 设备事件 | 否 | 保存在事件表，不直接变成长期记忆 |
| 第三方数据 | 受限 | 必须符合授权和用途限制 |

## 记忆读取流程

```text
用户消息
→ 读取当前对话短期上下文
→ 根据意图选择记忆类型
→ 按关键词、时间、来源查询相关记忆
→ 限制返回数量
→ 组装进 Agent 上下文
```

第一阶段检索方式：

- memory_type
- keywords
- title/content 关键词
- source_type/source_id
- 创建时间
- importance

不使用向量检索。

## Agent 使用记忆的规则

1. 只读取当前意图相关的记忆。
2. 不把全部历史记忆塞入 Prompt。
3. 不把未确认猜测当作事实。
4. 引用偏好时要保持结构化。
5. 用户要求忘记时必须能删除。
6. 记忆内容不能覆盖安全策略。

## 用户授权

需要显式授权：

- 摄像头或图像数据
- 语音记录
- 位置信息
- 健康相关数据
- 第三方账号数据

即使未来实现这些能力，也必须提供：

- 开关
- 查看入口
- 删除入口
- 导出能力

第一阶段不采集这些数据。

## 记忆重要性

建议评分：

| 分值 | 含义 |
| --- | --- |
| 1 | 临时上下文 |
| 2 | 一般事实 |
| 3 | 常用偏好 |
| 4 | 重要任务经验 |
| 5 | 用户明确要求长期记住 |

重要性影响：

- 是否进入长期记忆
- 检索排序
- 保留时间
- 上下文选择

## 记忆清理

| 类型 | 清理策略 |
| --- | --- |
| 短期上下文 | 会话结束后归档或清理 |
| 未确认记忆 | 超过 7 天未确认则删除或降级 |
| 低重要性记忆 | 可按配置清理 |
| 用户确认记忆 | 只有用户删除或明确过期时清理 |
| 任务记忆 | 长期保留摘要，原始日志按策略清理 |

## 隐私原则

1. API Key 和令牌不进入记忆。
2. 模型调用日志必须脱敏。
3. 用户可以查看已保存记忆。
4. 用户可以删除单条记忆。
5. 用户可以清空未确认记忆。
6. 记忆不用于绕过权限。
7. 不把记忆发送给无关 Provider。

## 数据表

使用 `memories` 和 `user_preferences` 两类表：

- `user_preferences` 保存结构化偏好键值。
- `memories` 保存事实、经验和摘要。

短期上下文来自对话消息表，不复制到长期记忆表。

## 测试要求

1. 记忆写入和读取。
2. 关键词检索。
3. 来源过滤。
4. 未确认记忆不进入长期上下文。
5. 用户删除后不再被检索。
6. 敏感数据不入库。
7. 保留策略生效。
8. Agent 只选择相关记忆。

## 未来扩展

1. 向量检索。
2. 记忆重写和压缩。
3. 用户可编辑记忆库。
4. 记忆来源图谱。
5. 多用户记忆隔离。

这些扩展不得改变当前安全边界。
