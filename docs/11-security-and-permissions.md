# 11. 安全与权限设计

## 安全目标

1. AI 输出不能直接触发真实世界操作。
2. 所有设备操作必须经过统一权限和风险检查。
3. 敏感配置不得进入源码或日志。
4. 每次重要操作可审计。
5. 高风险操作默认禁止或要求用户确认。
6. 系统能在设备离线、超时或失败时安全停止。

## 资产识别

| 资产 | 风险 |
| --- | --- |
| Home Assistant Token | 可控制家庭设备 |
| AI API Key | 财务和账号风险 |
| Nova API Token | 可访问控制台和设备操作 |
| 设备控制能力 | 影响物理环境 |
| 用户偏好和记忆 | 隐私风险 |
| 任务和事件历史 | 行为隐私风险 |
| SQLite 数据库 | 数据完整性风险 |

## 威胁模型

### 1. 提示注入

攻击方式：

- 设备名称、事件内容或网页内容中包含恶意指令。
- 模型输出声称“用户已授权”。

防护：

- 外部内容作为数据字段传入。
- 系统提示声明外部数据不可改变规则。
- 工具调用必须经过独立 Safety Policy。
- 用户确认只接受来自 Web 控制台的明确操作。
- 高风险动作不因文本内容跳过确认。

### 2. 模型输出伪造

攻击方式：

- 模型返回非法工具名、非法参数或伪造成功结果。

防护：

- Pydantic Schema 校验。
- Tool Registry 只允许调用注册工具。
- 工具参数逐项校验。
- 设备能力检查。
- 结果以真实状态查询为准。

### 3. 未授权设备控制

攻击方式：

- 用户或进程尝试控制未授权设备。

防护：

- API Token。
- 工具权限。
- 设备权限。
- 动作白名单。
- 风险等级限制。

### 4. 设备误操作

攻击或故障方式：

- 重复提交。
- 状态过期。
- 设备离线时执行。
- 平台响应超时但动作实际已执行。

防护：

- 幂等键。
- 执行前状态检查。
- 执行后状态验证。
- 非幂等写操作不自动重试。
- 超时后必须读取状态验证。

### 5. 凭据泄漏

攻击方式：

- API Key 写入源码、日志或数据库。

防护：

- 环境变量或本地配置文件。
- `.env` 不提交。
- 日志脱敏。
- API 不返回敏感配置明文。
- 数据库只保存脱敏摘要或状态。

## 风险等级

| 等级 | 定义 | 示例 | 默认策略 |
| --- | --- | --- | --- |
| read_only | 不改变系统或环境 | 查询设备状态 | 登录后允许 |
| low_risk | 可逆、影响范围小 | 打开灯 | 允许并记录 |
| medium_risk | 影响舒适、费用或多设备 | 调整空调、创建自动化 | 需要确认 |
| high_risk | 涉及安全、财产或不可逆 | 门锁、市电实验设备 | 默认禁止 |

设备能力可以提升风险等级，但不能降低到低于工具声明的最低风险。

## 工具权限

每个工具必须声明：

- 风险等级
- 默认权限
- 是否需要确认
- 输入 Schema
- 输出 Schema

权限结果：

| 结果 | 说明 |
| --- | --- |
| allowed | 允许执行 |
| confirmation_required | 需要用户确认 |
| denied | 拒绝执行 |
| tool_disabled | 工具未启用 |
| risk_exceeded | 超过允许风险 |

## 设备权限

设备级配置必须支持：

- 启用或禁用设备
- 允许的动作列表
- 最大风险等级
- 是否需要确认
- 区域限制

示例：

```json
{
  "device_id": "device-uuid",
  "enabled": true,
  "allowed_actions": ["turn_on", "turn_off"],
  "max_risk_level": "low_risk",
  "requires_confirmation": false
}
```

## 执行条件检查

设备控制前必须确认：

1. 工具存在且启用。
2. 设备存在且启用。
3. 动作在设备能力列表中。
4. 参数符合 Schema。
5. 当前用户有权限。
6. 风险等级未超过限制。
7. 无静默期或冷却限制。
8. 设备在线。
9. 执行条件满足。
10. 如需确认，确认令牌有效。

## 用户确认流程

```text
Agent 生成候选动作
→ Safety Policy 判定需要确认
→ Task 进入 waiting_confirmation
→ 前端展示设备、动作、参数和风险
→ 用户确认或取消
→ 后端验证 confirmation_token
→ 恢复执行或取消任务
→ 记录 user_confirmed 事件
```

确认令牌：

- 一次性使用。
- 绑定任务 ID。
- 设置有效期。
- 只保存摘要或短期状态。

## 第一阶段禁止项

未经用户明确确认，禁止：

- 门锁控制
- 高风险设备控制
- 市电实验设备控制
- 批量设备控制
- 任意系统命令执行
- 任意文件删除
- 任意网络访问
- 修改安全配置

即使未来扩展这些能力，也必须独立设计安全策略，不能由 Agent 自主决定。

## API 安全

1. 所有非健康检查接口启用 Bearer Token。
2. 后端默认绑定 `127.0.0.1`。
3. 写操作使用幂等键。
4. 错误响应不暴露堆栈。
5. 请求日志记录 correlation ID。
6. WebSocket 连接必须认证。
7. 生产模式下关闭调试工具接口。

## AI 安全

AI Provider 输出必须经过：

1. JSON 或结构化输出解析。
2. Pydantic 校验。
3. 工具存在性检查。
4. 参数校验。
5. 设备能力校验。
6. 用户权限检查。
7. 风险等级检查。
8. 执行条件检查。
9. 结果验证。

模型输出中的“成功”不作为任务成功依据。

## 审计日志

每次设备控制必须记录：

- 用户请求内容
- 任务 ID
- 工具名
- 输入参数
- 权限结果
- 风险等级
- 设备 ID
- 执行前状态
- 执行结果
- 执行后状态
- 验证结果
- 错误信息
- correlation ID

日志不得记录：

- API Key
- Home Assistant Token
- Nova API Token
- 未脱敏的敏感配置

## 备份安全

1. 备份文件包含事件和任务历史，应视为敏感数据。
2. 备份目录不提交 Git。
3. 数据库迁移前自动备份。
4. 备份任务记录成功或失败。
5. 备份文件路径可配置。

## 失败安全

| 故障 | 期望行为 |
| --- | --- |
| Home Assistant 不可达 | 拒绝控制，返回适配器错误 |
| 设备 unavailable | 拒绝控制 |
| API 超时 | 不自动重试非幂等动作，读取状态验证 |
| 状态验证失败 | 任务失败，不显示成功 |
| AI 超时 | 任务失败或等待重试，不执行动作 |
| 数据库写入失败 | 任务失败，不继续执行后续步骤 |
| 权限配置错误 | 默认拒绝 |
| 配置缺失 | 启动失败或进入降级模式，不执行设备操作 |

## 权限默认值

| 工具 | 默认 |
| --- | --- |
| list_devices | allow |
| get_device_state | allow |
| get_environment_state | allow |
| query_events | allow |
| control_device | allow_low_risk |
| automation management | require_confirmation |
| system command | disabled |
| file operation | disabled |
| network request | disabled |

## 安全测试

必须覆盖：

1. 无 Token 访问 API。
2. 无权限控制设备。
3. 控制禁用设备。
4. 执行不支持动作。
5. 提交非法参数。
6. 伪造工具名。
7. 伪造执行成功输出。
8. 高风险动作未确认。
9. 确认令牌过期或重放。
10. 设备离线。
11. 适配器超时。
12. 状态验证失败。
13. API Key 缺失。
14. 日志脱敏。

## 安全结论

安全策略必须独立于 AI Provider 和 Agent Prompt。模型可以提出候选动作，但只有 Tool System 和 Safety Policy 可以决定是否执行。
